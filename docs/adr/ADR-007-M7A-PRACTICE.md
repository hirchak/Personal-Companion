# ADR-007 — M7A deterministic packages, runtime receipts, persistent sessions

Status: implemented candidate within owner-authorized M7A; independent review pending.
A generic linear engine supports future mechanics without clinical activation or AI authority.
Consume existing validated canonical M7_PREP each admission check; never import candidate text into runtime.
Synthetic namespace/path and explicit config on marked roots are separate from production admission.
Typed runtime receipt binds module/version/package hash/preparation identity/implementation source hash,
owner decision/scope/epoch/creation time and optional expiry. Synthetic receipt is original-neutral UX only.
No production path can override canonical OFF; future production admission needs a separate authorized
registry/activation evolution and complete rights/approval/technical receipts.
Sessions pin exact package/version/receipt; admission drift blocks new transitions while retaining data.
No workflow expressions/branches/LLM, no new sync infrastructure. Existing SQLite/transactions/backups
add schema7 isolated practice tables; entry and health domain schemas unchanged. Restore invalidates
runnable bindings, no activation stored/restored. Stop/delete and ordinary journal remain independent.
