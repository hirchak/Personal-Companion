# Почати тут

## Що є у пакеті

Це єдина канонічна документація для Codex і для архітектора в ChatGPT.
Окремий ChatGPT-пакет — автоматично зібрана читабельна копія цих самих документів,
не друга незалежна специфікація. Версія 0.1.0; дата 2026-09-30.

Ім’я `Personal Companion` тимчасове. Не купувати домен і не створювати бренд без рішення власника.

## Покласти в проєкт Codex

1. Створити порожню папку майбутнього репозиторію. Розпакувати сюди вміст Repo Starter.
2. Не класти сюди приватний додаток, чужий експорт чатів, особисті записи або ключі.
3. Відкрити папку в Codex. Прочитати `prompts/M0_BOOTSTRAP.md`.
4. Обрати GPT-6.1 Sol, reasoning High, Plan Mode OFF для виконання M0.
   Якщо такого параметра немає, звірити доступний каталог; не вигадувати команду.
5. Передати коротку ціль із `prompts/GOAL_START.txt`.

M0 не є наказом реалізувати весь продукт. Це перевірка середовища, узгодження
контрактів, налаштування стану й план M1. Установка системних компонентів,
реальні AI-запити, мережеві інтеграції та публікація в M0 не дозволені.

## Створити ChatGPT Project

Вставити текст `context/PROJECT_INSTRUCTIONS.txt` у поле інструкцій проєкту.
Завантажити чотири Markdown-файли зі згенерованого ChatGPT Context-пакета.
Завантажувати саме розпаковані файли; не покладатися на автоматичне читання ZIP.
Копії не оновлюються разом із GitHub самі: їх потрібно перегенерувати та замінити.
Свіжий GitHub-коміт має пріоритет над старим snapshot щодо стану реалізації.

URL репозиторію: `https://github.com/hirchak/Personal-Companion.git`.
Актуальні visibility/default branch та review permissions мають збігатися у GitHub,
`.project/project.json` і STATE; URL не дозволяє merge/deploy.
В ChatGPT написати URL, review branch і SHA зі звіту; використовувати доступний
GitHub connector для читання. Public-доступ не дає ChatGPT автоматичного моніторингу.

## Що робити з приватним додатком

Він надається ОКРЕМО, не входить ні в repo ZIP, ні в стандартний ChatGPT ZIP.
Зберігати поза репозиторієм, не в папці з автоматичним хмарним backup без усвідомленої згоди.
Це чутливий текст, а не конфігурація застосунку. Не імпортувати його у vault
і не надсилати іншій моделі автоматично. Власниця даних має сама погодити використання.
Навіть ChatGPT Project є передаванням матеріалу зовнішньому сервісу.

## Перевірка документації

```sh
python3 scripts/check_docs.py
python3 -m unittest discover -s tests -v
python3 scripts/build_chatgpt_context.py
```

Перший скрипт перевіряє структуру й узгодженість пакета, не клінічну або програмну безпеку.
Третя команда створює `generated/chatgpt_context/`; цей каталог не потрібно комітити.
Результати перевірки цього стартового пакета наведені в `PACKET_VALIDATION.md`.

## Цикл подальшої роботи

ChatGPT задає обмежену ціль → Codex реалізує, тестує, оновлює стан → користувач
передає звіт → ChatGPT перевіряє diff/коміт/докази → ACCEPT або FIX_REQUIRED.
Публікація очищеної review-гілки можлива лише після явного дозволу власника.
Прийняття milestone та merge у main — окремі дії. Наступний milestone сам не починається.
